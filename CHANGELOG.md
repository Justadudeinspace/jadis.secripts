# Changelog

## 0.3.0 — 2026-10-28

- Added reusable content-first Image Intelligence: bounded Android, FDT/DTBO, ELF, uImage/FIT, compression/CPIO and AVB metadata inspection; explicit optional evidence providers.
- Added source-linked Recovery Device Models, conflicts, static tree diagnosis, candidate-only derivation with generated-line provenance, and conservative build planning.
- Added bounded recursive read-only corpus archaeology and public research lineage; no corpus code, keys or binaries incorporated.
- Added formal permanent CREDITS.md attribution/licensing review, linked from the README.
- Integrated Image Lab/model/planning discovery into the registry, recipes, cockpit and dossier.
- Hardware qualification and real TWRP compilation remain unproven; parsing is not verification.

## 0.2.0 — 2026-10-28

- Renamed the canonical CLI executable from `sec` to `js`; no permanent compatibility alias.
  `js 1337` is the master developer cockpit. The distribution and internal Python package retain their names.
- Expanded the existing typed registry to 63 inspection operations and 19 guided recipes, with explicit
  parameter contracts and network-recipe permission. Added developer dossier and stronger doctor states.
- Added live cockpit context, history/receipt filters, comparison, artifact lookup, ranked discovery
  and registry-derived Bash completion.
- Deepened SDK/JVM/Python/system evidence and privacy-preserving ADB/Fastboot dossiers.
- Extended static recovery graphs, boot/vendor_boot sections, bounded ramdisk/CPIO metadata, untrusted
  AVB parsing and reports with separate source/tree/build/image/device evidence states.
- Preserved safety controls, legacy exclusions and receipts. TWRP orchestration remains experimental;
  compilation and hardware qualification are not established by fixture tests.

## 0.1.0 — 2026-10-28

Initial Python arsenal: 20 registered diagnostic operations, five preparation recipes, sanitized
receipts, secret-aware archaeology, host diagnostics and an accessible 1337 console. Recovery Lab
introduced the TWRP backend, static tree audit, boot-header inspection, explicit source/build planning,
artifact collection and manual qualification reports. Source/build integration remained experimental;
actual compilation and hardware qualification were not established by that release.
